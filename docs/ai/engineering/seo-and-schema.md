# SEO and Schema

Canonical URLs, sitemap, robots.txt, OpenGraph meta, JSON-LD schema types, and OG image generation for chill-dogs.com.

## Use this when

Adding a new page, verifying meta tag compliance, or implementing structured data.

---

## Canonical URLs

Every page has a canonical URL enforced by `BaseLayout.astro`. The canonical is always the full production URL with trailing slash.

Format: `https://www.chill-dogs.com/path/`

`PUBLIC_SITE_URL` must be set in the build environment for correct canonical URL generation.

---

## Sitemap

Generated by `@astrojs/sitemap` with priority tuning:
- Homepage: 1.0
- Cooling/calming/comfort section collectors: 0.9
- Other pages: default

Hero experiment variant pages are `noindex` and excluded from the sitemap. Their canonical points to the production collector URL.

---

## Robots.txt

Generated by `astro-robots-txt`. Staging environments (where `VERCEL_ENV !== 'production'`) get `noindex, nofollow` injected by `BaseLayout.astro`.

---

## OpenGraph meta — enforced constraints

These constraints are tested by `src/__tests__/seo-meta.test.ts`. Failing them will cause `bun run test` to fail.

| Tag | Min chars | Max chars |
|---|---|---|
| `og:title` | 40 | 65 |
| `og:description` | 100 | 165 |

### og:title

Defaults to the `<title>` value formatted as `"Page Title | Chill-Dogs"`.

When the `<title>` value falls outside the 40–65 char range, use the `ogTitle` prop on `BaseLayout`:

```astro
<BaseLayout
  title="Page Title"
  ogTitle="Shorter Social Title | Chill-Dogs"
  ...
>
```

### og:description

`og:description` and `<meta name="description">` share the same value — one field, two uses.

Write the description for both humans and search. It should be specific, useful, and accurate — not teaser copy.

### og:image

General OG images are auto-generated during pre-build by `src/scripts/generate-og-images.mjs`. Product-style OG images for sitemap pages that define `heroProduct` are generated locally with `bun run og:force` and committed under `/public/og/<slug>.jpg`, so deploy builds do not fetch remote product images or render Satori templates. The generator also writes `src/scripts/og-gen/product-og-manifest.json`; tests compare that manifest to current sitemap inputs so stale committed JPGs are caught when the title, summary, theme, or hero product changes.

`BaseLayout.astro` auto-resolves the OG image path. No manual `og:image` configuration is needed for standard pages.

Use `heroProduct` only when one product should represent the page in a social preview. Product-led converters usually qualify; browse/search pages such as `/shop/`, broad informational collectors, and multi-product article collectors should stay on the general OG path. Product-style OG generation caches rendered JPGs and downloaded product image bytes in `.cache/og-gen/` for local regeneration.

`noindex` controls robots metadata only; it does not block generated social images. Routes without generated OG assets, including `/v/` variants, `404`, admin/internal pages, and legal policy pages, fall back to `/og-default.jpg`.

CTA text per page type is configured in `src/config/og-cta.mjs`.

## JSON-LD schema types

### Article

Used on: all article collector pages.

Required fields:
```js
{
  '@type': 'Article',
  headline: title,
  description,
  url: 'https://www.chill-dogs.com/...',
  image: ['...og-image-url...'],
  author: {
    '@type': 'Person',
    name: 'Benjamin Strawbridge',
    url: 'https://www.benstrawbridge.com/'
  },
  publisher: {
    '@type': 'Organization',
    name: 'Chill-Dogs',
    logo: { ... }
  }
}
```

Do not use `CollectionPage` type for article collectors.

### BreadcrumbList

Emitted by `BaseLayout.astro` on production only (`VERCEL_ENV === 'production'`). Do not add manually.

### CollectionPage

Used on section collector pages (`/cooling/`, `/calming/`, `/comforting/`). `SectionCollectorPage` renders the schema, and `src/data/section-collectors.ts` derives `hasPart` from the complete sitemap inventory so new matching articles and converters are included automatically. Topic subsection grouping affects rendered cards only; schema should include the complete matched inventory.

### FAQPage

Used on pages with an `FAQ` module when the FAQ has 3+ questions. Check existing converter pages for implementation reference.

### WebSite and Organization

Present on the homepage. Do not duplicate on other pages.

## Twitter/X card meta

Every page gets `twitter:card`, `twitter:title`, `twitter:description`, and `twitter:image` via `BaseLayout.astro`. These pull from the same OG values.

---

## Staging behavior

When `VERCEL_ENV !== 'production'` (staging, preview, development):
- `BaseLayout.astro` injects `<meta name="robots" content="noindex, nofollow">`
- BreadcrumbList JSON-LD is not emitted
- Pinterest pixel does not load

This means staging builds are always invisible to search engines.
